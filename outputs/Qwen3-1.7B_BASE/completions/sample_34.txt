3. **Odd Length Handling**: For odd `n`, the sequence is constructed similarly but with an additional element at the end to ensure the longest palindromic subsequence length is `ceil(n/2)`.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read
    data = input().split()
    t = int(data[0])
    idx = 1
    results = []
    for _ in range(t):
        n = int(data[idx])
        idx += 1
        if n % 2 == 0:
            k = n // 2
            first_part = [1, 1] + list(range(2, k + 1))
            second_part = list(range(k - 1, 0, -1))
            results.append(' '.join(map(str, first_part + second_part)))
        else:
            k = (n - 1) // 2
            first_part = [1, 1] + list(range(2, k + 1))
            second_part = [k + 1] + list(range(k, 0, -1))
            results.append(' '.join(map(str, first_part + second_part)))
    print('\n'.join(results))

if __name__ == '__main__':
    main()
```

### Explanation
1. **Reading Input**: The input is read in one go for efficiency, especially given the constraints.
2. **Even Length Handling**: For even `n`, the sequence starts with two `1`s, followed by increasing integers up to `n/2`, and then mirrors these values back to ensure the longest palindromic subsequence length.
3. **Odd Length Handling**: For odd `n`, the sequence starts similarly but adds an additional element at the end to ensure the longest palindromic subsequence length is `ceil(n/2)`.
4. **Output**: The results are collected in a list and printed at the end to ensure efficient output formatting.

This approach ensures that the longest palindromic subsequence length is maximized and the number of such subsequences exceeds the sequence length, thus satisfying the problem constraints.
